# 安心 · 家庭病历与复查管理

一个面向家属的中文病历管理工具，把扫描 PDF 整理为可核对的资料、历次指标折线图和有原文来源的分析报告。电脑负责保存原件与本地 OCR，手机可通过私人连接查看、上传和核对。

当前版本用于管理一位患者的资料，主要针对肿瘤随访场景。支持 Windows 桌面快捷方式和系统托盘，点击图标即可使用。

**仓库只包含程序代码、图标、测试和通用说明，不包含真实病历、个人分析报告、数据库、账户凭据或加密备份。** 首次从仓库安装得到空白工具，需要自行上传资料。

## 主要功能

| 页面 / 功能 | 用途 |
| --- | --- |
| 分析报告 | 根据已核对资料呈现重点、证据、局限和就诊问题；可以保存大模型生成的深入分析 |
| 历次对比 | 中文指标分类、阅读优先级、异常筛选、折线图、单位和各次参考范围 |
| 诊疗时间线 | 按报告实际日期串联诊疗和复查，保留原件入口 |
| 资料与核对 | 扫描原图与摘录并排显示，定位来源、旋转和放大，修正字段并保存历史 |
| 重复和无关页 | 相同文件不重复导入；相似扫描经人工核对后关联；发票等页面可移为无关页并恢复 |
| 上传与备份 | 新 PDF 本地识别、逐页状态、失败重试、加密备份恢复、就诊摘要打印与指标 CSV |
| 病历问答 | 授权连接 ChatGPT 后，基于已核对资料对话，保留资料版本和来源引用 |
| 桌面与托盘 | 无命令窗口启动、重复启动保护、状态提示、右键退出全部工具进程 |

资料的重要程度与核对状态分开：

- 阅读顺序：**核心资料 / 复查关注 / 背景备查**，允许人工调整。
- 核对状态：**已核对 / 待核对 / 存在冲突**；已核对仅表示摘录已对照原件。
- 与病情无关的页面移出默认核对列表及分析、趋势、时间线和导出，原件仍保留。

## 工作流程

```mermaid
flowchart LR
    A[上传 PDF] --> B[保存原件]
    B --> C[电脑本地 OCR]
    C --> D[检查重复与冲突]
    D --> E[人工核对及修正]
    E --> F[更新分析与历次趋势]
    F --> G[备份或打印就诊摘要]
```

未核对、已关联为重复或已移为无关页的记录不进入正式趋势及分析。重新识别不会覆盖已录入的人工修正；修订历史可追溯。

相同指标与兼容单位按检查次序绘制折线。检测方法明确一致时为实线，方法缺失或不同时为虚线，提示比较的不确定性；缺测、模糊数值和带大小于号的结果不当作精确点，也不跨过这些缺口连线。横轴表示检查顺序，不表示等长时间间隔。

## 技术结构

| 部分 | 实现 |
| --- | --- |
| 界面 | React 19、Vite 6、Lucide 图标，适配电脑与手机 |
| 服务 | Python 3.12、FastAPI、Uvicorn，默认仅监听 `127.0.0.1:8765` |
| 存储 | SQLite、原始 PDF、页面图像、摘录、核对状态与修订历史 |
| OCR | PaddleOCR 3.3.2、PaddlePaddle 3.2.2，电脑 CPU 本地识别 |
| 桌面运行 | pystray、Windows 托盘、实例锁和 Windows Job Object |
| 私人手机访问 | Tailscale Serve，需自行安装并登录 |
| 备份与凭据 | 密码加密备份；ChatGPT 凭据采用当前 Windows 用户的 DPAPI 加密 |

Windows 桌面启动、识别进程锁和凭据保护依赖 Windows API；本版本没有完成 macOS / Linux 支持。

## 安装与首次启动

### 环境准备

- Windows 10 / 11，64 位。
- Python 3.12，64 位。
- Node.js 22 和 pnpm 10。
- 首次安装需联网下载依赖与 OCR 模型。模型装好后，识别在本机完成；大模型问答另需联网和账户授权。

在项目文件夹打开 PowerShell，执行以下命令。所有 Python 依赖安装在项目的 `.venv` 内，前端依赖安装在 `node_modules` 内。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
pnpm install --frozen-lockfile
pnpm build
.\.venv\Scripts\python.exe -c "from store import init; init()"
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup_desktop.ps1
```

`requirements.lock.txt` 与 `pnpm-lock.yaml` 保存当前锁定版本。前端构建需要允许 esbuild 的构建脚本，项目已在 `pnpm-workspace.yaml` 中声明。

### 日常使用

1. 双击桌面或项目文件夹中的 **安心病历** 绿色爱心图标，打开浏览器中的本机工具。
2. 首次使用在电脑上填写患者姓名，设置至少 10 个字符的工具登录密码。
3. 在“上传与备份”导入 PDF，等待本地识别，再到“资料与核对”对照原件。
4. 确认日期、姓名、结论、数值、单位和参考范围后，设为“已核对”。
5. 在首页查看分析和就诊问题，在“历次对比”查看指标变化。

关闭网页会保留后台服务。右下角托盘可查看状态、打开工具和资料文件夹；选择 **退出并关闭全部进程** 才会停止本工具的网页、OCR 及子进程。如果图标隐藏，请点击时钟左侧的 **˄**。工具不自动随开机启动。

原有 `启动病历工具.cmd` / `停止病历工具.cmd` 仍可使用。移动项目文件夹后，重新运行 `setup_desktop.ps1` 生成快捷方式。

## 在手机上打开

1. 在电脑和手机安装 [Tailscale](https://tailscale.com/download)，登录同一个私人账户并连接。
2. 在电脑启动安心病历并完成本机密码设置。
3. 双击 `手机访问设置.cmd`，按提示完成 Tailscale 私人 HTTPS 设置。
4. 手机保持 Tailscale 已连接，在浏览器打开脚本显示的 HTTPS 地址，输入病历工具密码。

可把网址添加到手机主屏幕。电脑需要保持开机且不休眠；从托盘退出工具后，手机入口也暂时不可用。手机不能使用电脑的 `127.0.0.1` 地址。

脚本使用 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)，没有启用公开访问的 Funnel，也没有将病历服务直接监听到公网。

## 本地分析与大模型问答

首页包含基于已核对资料的本地规则解读、来源和医学参考。打开首页不会自动调用大模型。

“病历问答”提供可选的 ChatGPT 授权连接；首次连接在电脑本机完成。账户是否可用、可选模型及额度取决于服务方和账户返回的结果，仓库测试不代表真实账户已经授权或推理成功。

主动发送问题或生成深入分析前，界面提供发送范围预览并要求同意。上下文使用已核对、未重复且与病情有关的摘录与指标，不附原始 PDF、OCR 全文、文件名或姓名字段；自由文本仍可能包含身份信息，应自行检查。问答会将所选文字交给 OpenAI 云端处理，不能等同于完全离线功能。

账户凭据保存在本机 `data/private/`，使用 Windows DPAPI 加密，不提交到 GitHub，也不放入病历备份。换电脑或 Windows 账户后需重新授权。对话与保存的分析位于本机数据库，纳入病历备份；资料更新后，旧分析显示版本失效提示。

## 数据保存与备份

默认数据位置为项目的 `data/`：

```text
data/
├─ originals/        原始 PDF
├─ pages/            页面图像
├─ records.db        数据库、核对结果、修订、问题与对话
├─ private/          仅当前 Windows 用户可解密的账户凭据
├─ launcher.log      桌面和托盘运行日志
├─ server.log        网页服务日志
└─ ocr.log           识别服务日志
```

在“上传与备份”设置独立备份密码并下载 `.health` 加密文件。恢复时先在界面验证文件，再运行 `恢复备份.cmd`；当前数据保留到 `data-before-restore-时间戳`，恢复后重新启动工具。

**本机数据库和原始 PDF 本身未加密；加密的是导出的备份。** 备份密码丢失无法解密。备份不包含 Python / Node 环境、OCR 模型或 ChatGPT 登录凭据。代码仓库不能代替病历备份。

## 提交代码前

`.gitignore` 已排除原始 PDF、数据库、加密备份、个人整理文档、日志、凭据、快捷方式、依赖及构建产物。提交前仍需检查 `git diff --cached`，尤其是新加入的文档、图片和自由文本；不要用 `git add -f` 强行加入个人资料。

测试使用通用样例，不应把真实姓名、报告编号或个人数值写入示例、截图、Issue 或提交信息。

## 适用边界

本工具帮助整理资料、理解变化和准备就诊沟通。OCR 和自动分类可能出错，应对照原件；报告异常与指标变化分别展示，不据此自动判断复发、病情恶化或决定治疗。实际医疗判断由诊治医生结合完整病历、症状与检查完成。
